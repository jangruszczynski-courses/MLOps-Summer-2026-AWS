# NVIDIA Triton – Image Classification Demo

A minimal end-to-end example for students showing how to:
1. Export a pretrained PyTorch model to ONNX.
2. Serve it with **NVIDIA Triton Inference Server** (CPU mode).
3. Query it from Python over **gRPC**.

---

## Repository layout

```
host/
├── export_onnx.py                      # Step 1 – export model
├── client.py                           # Step 3 – send an image to Triton
├── docker-compose.yml                  # Step 2 – run Triton
├── pyproject.toml
└── model_repository/
    └── image_classifier/
        ├── config.pbtxt                # Triton model config (batching disabled)
        └── 1/
            └── model.onnx              # generated by export_onnx.py
```

---

## Quick start

### 0. Install Python dependencies

```bash
pip install -e .
```

### 1. Export the model to ONNX

```bash
python export_onnx.py
```

This downloads **MobileNetV3-Small-0.5** (~1.6 M parameters, pretrained on
ImageNet-1k) and writes `model_repository/image_classifier/1/model.onnx`.

### 2. Start Triton

```bash
docker compose up
```

Triton will scan `model_repository/`, load the ONNX model, and expose:

| Port | Protocol | Purpose            |
|------|----------|--------------------|
| 8000 | HTTP     | REST API           |
| 8001 | gRPC     | gRPC API (used here) |
| 8002 | HTTP     | Prometheus metrics |

> **GPU users** – uncomment the `deploy` block in `docker-compose.yml`
> (requires the NVIDIA Container Toolkit).

### 3. Run the client

```bash
# With your own image:
python client.py photo.jpg

# Without an image – a synthetic test pattern is created automatically:
python client.py
```

## Key concepts shown

| File | Concept |
|------|---------|
| `export_onnx.py` | PyTorch → ONNX export, `torch.onnx.export` |
| `config.pbtxt` | Triton model config, `max_batch_size: 0` disables batching |
| `client.py` | `tritonclient.grpc`, building `InferInput` / `InferRequestedOutput` |

### Why `max_batch_size: 0`?

Setting `max_batch_size: 0` in `config.pbtxt` tells Triton that this model
does **not** support dynamic batching.  Every request must include the full
tensor shape (batch dimension included), which here is always `[1, 3, 224, 224]`.

### Preprocessing

The client applies the same transforms used during training:

1. Resize to 224 × 224 (bilinear)
2. Scale pixels to `[0, 1]`
3. Normalise with ImageNet mean `[0.485, 0.456, 0.406]`
   and std `[0.229, 0.224, 0.225]`
4. Convert HWC → CHW, add batch axis → `[1, 3, 224, 224]`
